A brain is the unit of *publication*. If somebody might want one subject without the other four, those are five
brains — each publishable, installable and droppable on its own.

What a project adds is the part they share: one actor, one retention policy, one embedder, one registry account.

```console
vitruvio project init coursework --actor you@example.com
vitruvio project add optics --description "optics notes"
vitruvio project add acoustics-ii
vitruvio project add dynamics
vitruvio project show
```

```toml
[project]
name = "coursework"

[actor]
id = "you@example.com"

[brains.optics]
path = "./brains/optics"
description = "optics notes"

[brains.acoustics-ii]
path = "./brains/acoustics-ii"
```

A project answers two questions the rest of this section takes in turn: [which brain a command means](/projects/selecting-a-brain), and [where each brain publishes](/projects/publishing-a-project).

## Names are repository components

`acoustics-ii`, not `Acoustics II`. Lowercase letters, digits and single separators. Checked when the file is read
rather than when the artifact is pushed — a registry rejecting the name after a pack gives an error that says nothing
about which of the two names was wrong.

## Removing

```console
vitruvio project remove acoustics-ii
```

Unregisters it and prints where the layout still is. It never deletes: "remove it from this project" and "destroy it"
are different requests, and a brain may be the only copy of what it holds.
